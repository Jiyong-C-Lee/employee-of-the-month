# @narre/ui

게임이 공유하는 얇은 UI 층. 디자인 토큰(CSS 커스텀 프로퍼티)과 공통 셸(헤더·허브 복귀 링크)만 담는다.

**게임 화면·컴포넌트는 여기 두지 않는다.** UI가 게임마다 실제로 다르다. sultan은 카드 한 장 놓고 문답이고, eotm은 실시간 피드에 만화컷에 공유 카드까지 있고, speedword는 타이머 경쟁이다. 공유되는 것은 색·타이포·간격과 헤더뿐이다.

빌드 단계가 없다. 소스를 그대로 export하고 게임의 Vite가 컴파일한다(eotm `@eotm/shared` 관례).

## 사용

```tsx
import '@narre/ui/tokens.css';
import { Shell } from '@narre/ui';

export function App() {
  return (
    <Shell>
      <Game />
    </Shell>
  );
}
```

`Shell`은 **접힘 헤더**다. 게임 화면 좌상단에 narre 로고 칩만 상시 떠 있고, 탭하면 [홈으로]와 [내 정보 자리]가 펼쳐진다. 트리거는 탭으로 통일한다 — 호버는 모바일에 없다.

칩은 `position: fixed`라 레이아웃 자리를 차지하지 않는다. 게임은 셸을 몰라도 자기 화면을 그대로 그리면 된다. 게임마다 레이아웃이 달라서 셸이 자리를 먹으면 게임이 그만큼을 비켜 그려야 하기 때문이다.

내 정보 자리는 계정 도입 전까지 비어 있다. 이탈 확인 팝업 여부와 게임별 칩 위치 조정은 실제 화면을 보고 정한다(스펙 §6).

게임 CSS는 `--narre-*` 변수만 참조하고 리터럴 색·크기를 직접 쓰지 않는다.

## 왜 프레임워크는 통일하고 컴포넌트는 통일하지 않나

스택 통일로 세 게임이 전부 React + Vite로 간다(스펙 §2). 빌드 파이프라인·타입 시스템·플랫폼 훅이 하나가 되면 앞으로 계정·기록·랭킹 같은 플랫폼 기능을 한 번만 만들면 된다.

반면 화면은 게임 그 자체라 공유할 것이 거의 없다. 억지로 공통 컴포넌트를 만들면 게임마다 다른 요구가 props로 새어 나와, 결국 어느 게임에도 안 맞는 물건이 된다. 그게 `@narre/cf` 이전 판이 겪은 일이다.
